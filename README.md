# 먀로또

`assets/Frame2.png`를 사용하는 정적 웹 추첨기입니다. PNG 프레임 뒤쪽의 입 위치에 슬롯머신형 릴을 렌더링하며 GitHub Pages에서 별도 빌드 없이 실행됩니다.

## 화면 구성

오른쪽 컨트롤 영역은 두 탭으로 분리됩니다.

- `자동 번호 발급`: 무작위 번호를 1회 또는 지정 횟수만큼 연속 자동 발급하고 기록
- `추첨기`: 미리 정해 둔 번호를 숨겨 놓은 뒤 실제 추첨처럼 릴을 돌려 하나씩 공개하고, 완료 후 자동 발급 기록과 비교

## 자동 번호 발급

### 기본

- 번호 범위와 발급 개수를 지정
- 이미지 클릭 또는 `Space` 1회: 모든 릴 회전 시작
- 다시 클릭 또는 `Space`: 왼쪽부터 순차 감속/확정
- 결과는 자동 발급 기록에 저장

### 연속 자동

- 연속 실행 횟수를 `1~100회`로 지정
- 이미지 클릭 또는 `Space` 1회로 시작
- 기본 자동 번호 발급을 지정 횟수만큼 반복
- 각 회차 결과를 자동 발급 기록에 저장
- 실행 중 다시 누르면 현재 회차를 마친 뒤 중지

### 공통 설정

- 번호 범위 설정 가능
- 발급 개수 `1~7` 설정 가능
- 중복은 항상 비허용
- 번호 범위, 발급 개수, 발급 방식, 연속 횟수는 `localStorage`에 저장
- Web Crypto API 기반 번호 생성
- 최근 200회 자동 기록
- 현재 결과 / 개별 기록 / 전체 기록 복사 시 번호만 복사
- `전체 복사`는 한 줄에 한 조합 형식
- 날짜와 시간은 저장·표시·복사하지 않음

## 추첨기

### 미리 만든 번호 추첨

- 추첨할 번호를 공백·쉼표·세미콜론으로 구분해 `1~7개` 입력
- `추첨 준비`를 누르면 입력한 실제 번호는 화면에서 숨기고 준비 상태만 표시
- 첫 번째 이미지 클릭 또는 `Space`: 준비한 개수만큼 모든 릴 회전 시작
- 이후 입력 1회마다 왼쪽 릴 하나만 감속·정지하며 번호 하나를 공개
- 예를 들어 7개 번호라면 총 8회의 입력으로 완료
  - 1회: 7개 릴 전체 회전 시작
  - 2~8회: 1번부터 7번 릴까지 하나씩 공개
- 한 릴이 감속 중일 때 추가 입력은 무시해 중복 정지를 방지
- `번호 다시 입력`으로 새로운 미리 만든 번호를 준비 가능
- 입력한 번호와 보너스 설정은 `localStorage`에 보관

### 보너스 번호

- 기본값은 보너스 미사용
- 보너스 미사용 시 추첨 번호 `1~7개`를 그대로 하나씩 공개
- 보너스 사용 시 기본 당첨 번호를 정확히 6개 입력하고 보너스 번호 1개를 추가
- 이 경우 총 7개 릴 중 마지막 릴이 보너스 번호로 공개

### 자동 발급 번호 확인

미리 만든 번호 추첨이 끝나면 `자동 번호 발급` 탭의 저장 기록 전체를 자동으로 비교합니다.

- 보너스 미사용: 각 기록을 `N개 일치`로 표시
- 보너스 사용 + 당첨 번호 6개 기준: 로또 방식으로 순위 판정
  - 6개 일치: 1등
  - 5개 + 보너스: 2등
  - 5개: 3등
  - 4개: 4등
  - 3개: 5등
  - 그 외: 낙첨
- 일치한 번호와 보너스 일치 번호를 구분해 강조
- `다시 확인`으로 현재 자동 발급 기록을 재검사 가능

### 외부 번호 일괄 확인

- 여러 조합을 한 줄에 한 조합씩 붙여넣어 현재 추첨 결과와 일괄 비교
- 각 번호는 공백·쉼표·세미콜론으로 구분 가능
- `발급 기록 넣기`로 현재 자동 발급 기록을 입력 영역에 바로 불러올 수 있음

## 이미지와 레이어

Base64나 별도 이미지 로더를 사용하지 않습니다.

```text
assets/Frame2.png
```

릴 Canvas는 PNG 프레임보다 낮은 `z-index`에 배치되어 입 구멍을 통해서만 보입니다. 페이지와 이미지가 축소·확대되어도 입 위치와 릴 크기는 비율로 함께 조정됩니다.

## 실행

별도 빌드 과정이 없습니다.

```bash
python -m http.server 8080
```

또는 GitHub Pages에서 `main` / `/ (root)`를 배포 대상으로 지정하면 바로 실행할 수 있습니다.
