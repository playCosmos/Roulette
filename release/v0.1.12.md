# RouletteBridge v0.1.12

별풍선 자동 티켓 발급 기준을 명확히 분리하고, 기본 동작을 **단일 후원 기준**으로 변경한 릴리스입니다.

## 주요 변경 사항

- 기본 발급 모드를 `single_donation`으로 변경
- 기본 50개 기준에서 **한 번의 후원이 50개 이상일 때만** 티켓 발급
- 50개 미만 후원은 다음 후원과 합산해서 발급하지 않음
- 단일 후원 50개 → 1장, 120개 → 2장 발급
- 50개 미만 후원 및 단일 후원에서 남은 수량은 통계용 카운트로만 유지
- 기존 누적 발급 방식은 `cumulative` 모드로 별도 유지
- 관리자 페이지에 `단일 후원 기준 / 누적 후원 기준` 선택 추가
- 단일 후원 모드에서 수동 누적 보정은 티켓을 생성하지 않고 카운트만 변경
- 관리자 후원자 목록의 잔여값을 단일 후원 모드의 미발급 카운트 기준으로 표시
- Phase D/F 테스트를 단일 후원/누적 후원 모드 모두 검증하도록 확장

## 기본 동작 예시

`balloonsPerTicket = 50`, `issuanceMode = single_donation` 기준:

- 30개 후원 → 발급 없음
- 이후 25개 후원 → 발급 없음 (`30 + 25` 합산 발급 안 함)
- 50개 단일 후원 → 1장 발급
- 120개 단일 후원 → 2장 발급
- 이전에 남은 카운트는 이후 후원과 합산해 발급권으로 사용하지 않음

## 설정

신규 설치의 기본 설정:

```json
"ticket": {
  "balloonsPerTicket": 50,
  "numberMax": 28,
  "numberCount": 7,
  "issuanceMode": "single_donation"
}
```

기존 v0.1.11의 `config.json`에 `issuanceMode`가 없어도 v0.1.12에서는 `single_donation`으로 해석합니다. 관리자 페이지에서 설정을 저장하면 해당 값이 `config.json`에 기록됩니다.

## 다운로드

- `RouletteBridge-Windows-x64-v0.1.12.zip`: 전체 Windows x64 패키지
- `RouletteBridge-Patch-v0.1.11-to-v0.1.12.zip`: 기존 v0.1.11 설치용 패치

### 패치 ZIP 사용 방법

1. 실행 중인 RouletteBridge를 트레이 메뉴에서 완전히 종료합니다.
2. 기존 설치 폴더를 백업합니다.
3. 패치 ZIP의 내용을 기존 v0.1.11 설치 폴더에 그대로 덮어씁니다.
4. `RouletteBridge.exe`를 다시 실행합니다.

패치 ZIP에는 `config.json`, `data/`, `tickets/`, `backups/`, `runtime/`가 포함되지 않아 기존 설정과 운영 데이터를 덮어쓰지 않습니다.

## 검증

Windows Release CI에서 다음 항목을 통과한 패키지만 게시합니다.

- Admin / Channel Analyzer / Overlay JavaScript 문법 검사
- Java 25 Maven build
- Phase D 단일 후원/누적 후원 발급 테스트
- Phase E PNG 저장 테스트
- Phase F 복구 및 운영 테스트
- encoding probe
- Windows GUI/Tray app-image 생성
- 패키지된 EXE Phase F/encoding probe
- 내장 Java runtime 확인
- 배포 기본값 `issuanceMode = single_donation` 확인
- 관리자/오버레이/채널 분석 자산 포함 확인
- 배포용 `streamerId` 공란 확인
- 배포본에 로그 폴더가 사전 생성되지 않는지 확인
