# RamyaniGamesServer

방송용 게임을 서버가 제공하고, 참가자는 브라우저 기반 클라이언트만 사용하는 구조다.

## 현재 모듈

- Board: 멀티플레이 보드게임
- Roulette: 기존 구현은 별도 레거시/독립 경로로 유지하며 현재 GamesServer 패키지에는 포함하지 않는다.

## 서버 / 클라이언트 경계

- Admin HTTP: 127.0.0.1:17830
  - 룸 생성, 확정, 수동 턴, 위치 보정, 일시정지/재개, 연장, 종료
  - 외부 참가자에게 공개하지 않는다.
- Client HTTP: 0.0.0.0:17832
  - games/board 정적 클라이언트
  - 룸/런타임 GET만 허용
  - 관리 POST 요청은 허용하지 않는다.
- Client WebSocket: 0.0.0.0:17831
  - board.turn 실시간 상태 전달

## 룸 공유

룸을 확정하면 운영 페이지로 이동한다. 운영 페이지 상단의 공용 오버레이 URL 하나를 모든 참가자에게 전달한다. 각 참가자는 동일 URL을 자신의 OBS 브라우저 소스에 사용한다.

외부 인터넷 공유 시 config.json의 server.publicBaseUrl과 server.publicWebSocketUrl을 설정한다.


## 짧은 룸 코드 / 공유 URL

새 룸 ID는 기본 6자리 영문+숫자 코드로 생성한다. 혼동하기 쉬운 O/0, I/1은 사용하지 않는다.

예: `ABC7K2`

참가자에게 전달하는 보드 오버레이 URL은 룸 ID 외의 런타임 파라미터를 노출하지 않는다.

- 일반 보드: `https://games.example.com/games/board/index.html?roomId=ABC7K2`
- 직각 보드: `https://games.example.com/games/board/rect.html?roomId=ABC7K2`

보드 클라이언트는 `/api/client/config`에서 WebSocket 주소를 자동 조회한다. 기존 UUID 형식의 룸 ID도 계속 조회할 수 있다.


## 원격 관리자

게임 서버 PC와 실제 운영자가 다른 PC일 수 있으므로 관리자 UI도 외부 공용 HTTP 포트에서 인증 후 사용할 수 있다.

- 서버 관리 콘솔: `127.0.0.1:17830`
- 참가자/원격 관리자 공용 HTTP: `0.0.0.0:17832`
- 실시간 WebSocket: `0.0.0.0:17831`

외부 운영자는 오버레이와 동일한 호스트/포트에서 `/admin/` 경로를 사용한다.

예:

`http://PUBLIC-IP:17832/admin/?token=<server-generated-token>`

최초 토큰 검증에 성공하면 서버는 토큰을 URL에서 제거하고 12시간 관리자 세션 쿠키를 발급한다. 쿠키는 `HttpOnly`, `SameSite=Strict`이며 HTTPS 공개 주소에서는 `Secure`도 적용한다.

관리자 API의 변경 요청은 17832에서 인증을 확인한 후 내부 `127.0.0.1:17830`으로 프록시한다. 따라서 17830은 포트포워딩하지 않는다.

서버 PC의 17830 서버 관리 콘솔에서 현재 원격 관리자 링크를 확인/복사할 수 있다. bootstrap token과 관리자 세션은 `data/board-game.db`에 영속화되므로 일반 서버 재시작이나 프로그램 덮어쓰기 후에도 유지된다. 단, 세션은 마지막 사용 시점 기준 12시간 sliding TTL을 적용하며, `모든 관리자 세션 해제` 또는 `관리자 인증 링크 재발급`을 실행하면 명시적으로 무효화된다.


## 사용자 진입 포트 통일

사용자(룸 생성자/운영자)와 참가자는 모두 외부 공용 HTTP 포트 17832를 사용한다.

- 운영자: `http://HOST:17832/admin/`
- 참가자: `http://HOST:17832/games/board/...?...roomId=...`
- 실시간 WebSocket: `17831`
- 실제 서버 관리 백엔드: `127.0.0.1:17830`

17830은 서버 자체 관리 콘솔과 내부 관리 API로 사용하고, 게임 운영자/참가자의 사용자 진입점은 17832로 유지한다.


## SOOP 프로필 이미지

룸 생성 시 각 참가자의 SOOP ID를 사용자 검색 API로 확인한다.

- 표시 이름이 비어 있으면 SOOP 현재 닉네임을 사용한다.
- 프로필 이미지가 비어 있으면 표시 이름 입력 여부와 관계없이 SOOP `station_logo` / `profile_image`를 조회한다.
- 조회된 URL은 룸 설정과 DB에 저장되어 모든 보드 클라이언트에 전달된다.
- 보드의 플레이어 말은 원형 SOOP 프로필 이미지를 우선 표시한다.
- 이미지 URL이 없거나 이미지 로딩이 실패하면 기존 닉네임 글자 말로 자동 대체한다.
- 관리자 참가자 상태 카드에서도 조회된 프로필 이미지를 확인할 수 있다.


## 17830 서버 관리 콘솔

실제 서버 PC에서 `http://127.0.0.1:17830/`을 열면 룸 운영 화면이 아니라 서버 자체 관리 콘솔을 표시한다. 17830은 계속 `127.0.0.1` 로컬 전용이며 포트포워딩 대상이 아니다.

표시 항목:
- 활성 원격 관리자 인증 세션 수
- 현재 WebSocket 연결 수
- SOOP 연결 상태와 Streamer ID
- 서버 버전과 룸 관리 UI 버전
- 서버 인스턴스 ID, 시작 시각/가동 시간
- 17830/17832/17831 엔드포인트와 DB 경로
- 현재 원격 관리자 인증 링크와 서버 PC용 사용자 관리자 링크
- 활성 보드게임 룸 수와 활성 룸 상한
- 각 활성/일시정지 룸의 룸 이름, 룸 코드, 상태, 참가자 수, 활성 시작 시각, 진행시간, 남은시간, 만료 예정 시각, 대기 후원 수

관리 작업:
- 활성 룸 상한 변경: 기본값 1, 허용 범위 1~32. 값은 DB의 서버 정책으로 저장되어 재시작 후에도 유지된다.
- 특정 룸 종료: 목록에서 선택한 룸 하나만 명시적으로 `TERMINATED`로 전환하고 해당 룸의 대기 후원만 정리한다.
- 모든 관리자 세션 해제: 현재 로그인된 17832 관리자 세션만 끊고 기존 인증 링크는 유지한다.
- 관리자 인증 링크 재발급: 모든 관리자 세션을 끊고 bootstrap token을 새로 만들어 이전에 전달한 링크까지 무효화한다.
- SOOP 재연결: 현재 SOOP 연결을 수동으로 재시도한다.
- 사용자 관리자 열기: 서버 PC에서 17832 룸 운영 UI를 새 창으로 연다.

활성 룸 상한은 admission control로만 사용한다. 예를 들어 활성 룸이 3개인 상태에서 상한을 1로 낮추면 기존 3개 룸의 보드 위치, 턴 상태, 일시정지 상태, 대기 후원, 만료시간을 변경하거나 자동 종료하지 않는다. 관리 화면에는 `3 / 1 초과` 상태만 표시되고 새로운 룸 활성화만 차단된다. 현재 룸을 종료하려면 해당 룸의 종료 버튼을 별도로 눌러야 한다.

여러 룸이 활성화된 경우 후원 입력은 기존 룸 매칭 조건을 만족하는 모든 활성 룸에 독립적으로 처리된다. 따라서 동일한 SOOP ID와 동일한 턴 실행 별풍선 조건을 여러 활성 룸에 중복 배치하면 하나의 입력이 여러 룸에 동시에 적용될 수 있다.

## 버전 표기 정책

17832 룸 관리 페이지와 17830 서버 관리 콘솔에서 아래 두 버전을 각각 표시한다.

- 룸 관리 UI 버전
- 서버 버전

두 값은 별도 필드로 관리하며, 동일 릴리스에서는 같을 수 있지만 이후 UI-only/server-only 변경이 생기면 독립적으로 증가할 수 있다. 배포 안내에도 두 버전을 함께 명시한다.


## 룸 생성 UI 정책

17832의 보드게임 룸 생성 페이지에서는 서버 상태 패널을 표시하지 않는다. SOOP 상태, Streamer ID, WebSocket, DB 경로, 외부 공유 상태, 활성 룸 상세 관리는 17830 서버 관리 콘솔에서 확인한다. 룸 생성 페이지에는 원격 관리자 링크와 룸 관리 UI 버전/서버 버전만 유지한다.

참가자 수는 별도 숫자 입력으로 설정하지 않는다. 기본 4개의 참가자 행으로 시작하며, 각 참가자 행 앞의 삭제 버튼과 마지막 행 아래의 참가자 추가 버튼으로 1~6명을 구성한다. 참가자가 P1 한 명만 남은 상태에서 삭제를 누르면 행을 제거하지 않고 SOOP ID/표시 이름/턴 실행 별풍선/방송 확인 상태를 기본값으로 초기화한다.

공통 턴 실행 별풍선은 별도 공통 입력 박스를 사용하지 않는다. P1의 `턴 실행 별풍선` 라벨 옆 `모두 동일` 체크박스를 사용한다. 체크 시 P1 값이 전체 참가자에게 적용되고 P2 이후 값은 직접 수정할 수 없으며, 체크 해제 시 참가자별 값을 독립적으로 수정할 수 있다.
