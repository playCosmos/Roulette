# 먀로또

`assets/Frame2.png`를 사용하는 정적 웹 추첨기입니다. PNG 프레임 뒤쪽의 입 위치에 슬롯머신형 릴을 렌더링하며 GitHub Pages에서 별도 빌드 없이 실행됩니다.

## 화면 구성

오른쪽 컨트롤 영역은 두 탭으로 분리됩니다.

- `자동 번호 발급`: 기본 자동, 연속 자동, 사용자 지정 수동 티켓 출력
- `추첨기`: 실제 추첨처럼 모든 릴을 먼저 회전시킨 뒤 사용자가 한 번 누를 때마다 그 순간 새로운 번호를 하나씩 무작위 추첨

## 자동 번호 발급

### 기본

- 번호 범위와 발급 개수를 지정
- 이미지 클릭 또는 `Space` 1회: 모든 릴 회전 시작
- 다시 클릭 또는 `Space`: 왼쪽부터 순차 감속/확정
- 결과는 발급 기록에 저장

### 연속 자동

- 연속 실행 횟수를 `1~100회`로 지정
- 이미지 클릭 또는 `Space` 1회로 시작
- 기본 자동 번호 발급을 지정 횟수만큼 반복
- 각 회차 결과를 발급 기록에 저장
- 실행 중 다시 누르면 현재 회차를 마친 뒤 중지

### 수동 티켓 출력

수동 모드는 번호를 추첨하거나 릴을 회전시키는 모드가 아니라 **사용자가 지정한 번호로 티켓 PNG만 생성하는 모드**입니다.

- 발급 방식에서 `수동` 선택
- 티켓 시트 형식에 맞춰 `1~28` 중 서로 다른 번호 `7개`를 사용
- 자동 번호 발급의 번호 범위/발급 개수 설정은 수동 모드에서 사용하지 않음
- 사용자 지정 번호 입력란에서 한 줄을 한 조합으로 인식
- 공백, 쉼표, 세미콜론, `/`로 번호 구분 가능
- 여러 줄을 입력하면 여러 조합을 한 번에 출력
- 한 번에 최대 100조합 지원
- 각 줄에 번호가 정확히 7개 있어야 하며 범위 초과·중복 번호는 거부
- `이미지 출력` 체크박스가 켜져 있어야 실행
- 이미지 클릭 또는 `Space` 1회로 입력된 모든 조합의 PNG 생성 시작
- 수동 모드에서는 릴을 돌리거나 순차 정지하지 않음
- 수동 번호는 자동 발급 기록에 추가하지 않음
- 각 조합마다 yellow / red / green / blue 시트 중 하나를 독립적으로 무작위 선택
- 마지막 수동 입력값과 수동 모드 선택은 `localStorage`에 유지

입력 예시:

```text
1 5 9 13 18 24 28
2 6 10 14 19 25 27
3 7 11 15 20 23 26
```

위 예시는 한 번 실행하면 티켓 PNG 3장을 생성합니다.

### 공통 설정

- 자동 발급 번호 범위 설정 가능
- 자동 발급 개수 `1~7` 설정 가능
- 중복은 항상 비허용
- 번호 범위, 발급 개수, 발급 방식, 연속 횟수, 수동 번호 입력값은 `localStorage`에 저장
- 자동 번호 생성에는 Web Crypto API 사용
- 최근 200회 자동 발급 기록
- 현재 결과 / 개별 기록 / 전체 기록 복사 시 번호만 복사
- `전체 복사`는 한 줄에 한 조합 형식
- 날짜와 시간은 저장·표시·복사하지 않음

## 티켓 PNG 출력

자동 번호 발급 탭의 `이미지 출력` 체크박스로 PNG 생성 여부를 선택합니다. 체크하지 않으면 기본/연속 자동 발급은 번호만 생성하며 이미지 파일은 만들지 않습니다.

현재 저장소의 4색 시트와 전용 출력 폰트를 사용합니다.

```text
assets/yellow.png
assets/red.png
assets/green.png
assets/blue.png
assets/font.ttf
```

네 장 모두 AI 생성 이미지라 위치가 완전히 동일하지 않으므로 `ticket-renderer.js`에서 **색상별로 닉네임 칸, 1~28 번호 위치, 하단 선택 번호 7칸 좌표를 각각 따로 보정**합니다.

`assets/font.ttf`는 PNG에 새로 합성되는 모든 텍스트에 사용합니다. 즉 우측 닉네임, 선택된 번호판 안의 흰 숫자, 하단 선택 번호 7칸이 같은 전용 폰트로 렌더링됩니다. PNG 생성 전에 브라우저의 `FontFace` API로 폰트를 먼저 로드한 뒤 Canvas에 적용하며, 폰트 로드가 실패한 경우에만 기존 기본 폰트로 대체합니다.

이미지 출력 시:

- yellow / red / green / blue 중 사용 가능한 시트 1장을 매 조합 무작위 선택
- 우측 닉네임 칸에 입력한 닉네임을 검은 글자로 합성
- 1~28 번호판에서 해당 7개 번호 위치를 검은색으로 채우고 흰 숫자로 다시 표시
- 하단 `선택 번호` 7칸에 같은 번호를 검은 글자로 표시
- 합성된 텍스트에는 `assets/font.ttf` 사용
- 합성 결과를 PNG로 다운로드
- 기본 발급과 `연속 자동`의 각 회차도 이미지 출력이 체크된 경우 각각 별도 PNG 저장
- 수동 모드는 여러 줄의 사용자 지정 조합을 한 번에 순차 생성·다운로드
- 닉네임과 이미지 출력 체크 상태는 `localStorage`에 보관
- 파일명에는 닉네임, 시트 색상, 번호만 포함하고 날짜/시간은 넣지 않음

자동/연속 발급에서 시트 이미지 출력은 번호 범위가 정확히 `1~28`, 발급 개수가 `7개`인 경우에만 동작합니다. 수동 모드는 시트 규격 자체가 `1~28 / 7개`로 고정됩니다.

브라우저에 따라 여러 PNG를 연속 다운로드할 때 최초 한 번 `여러 파일 다운로드 허용` 확인이 나타날 수 있습니다.

## 추첨기

추첨기 탭은 미리 정해 둔 번호를 순서대로 보여주는 방식이 아니라 **실시간 무작위 추첨 방식**입니다.

- 번호 범위와 추첨 개수를 별도로 지정
- 추첨 개수 `1~7` 지원
- 중복은 항상 비허용
- 추첨기 설정값은 `localStorage`에 저장
- 보너스 번호 기능 없음
- 첫 번째 이미지 클릭 또는 `Space`: 지정된 개수의 릴을 모두 회전 시작
- 이후 입력 1회마다 왼쪽 릴 하나만 정지
- 정지할 번호는 회전 시작 시 미리 만들지 않고 **해당 릴을 멈추는 입력이 발생한 순간 Web Crypto API로 새로 추첨**
- 이미 나온 번호는 후보에서 제외하므로 한 추첨 안에서 중복되지 않음
- 예를 들어 7개를 추첨하면 총 8회의 입력으로 완료
  - 1회: 7개 릴 전체 회전 시작
  - 2~8회: 1번부터 7번 릴까지 각각 실시간 번호 추첨 및 공개
- 한 릴이 감속 중일 때 추가 입력은 무시해 중복 정지를 방지
- 마지막 릴이 정지하면 추첨 완료
- 완료된 실제 추첨 번호 자체는 자동 번호 발급 기록에 섞어 저장하지 않음

## 참가자 번호와 결과

추첨기 탭에서는 여러 사람의 번호를 등록해 **한 번의 실시간 추첨 결과를 사람별로 동시에 판정**합니다.

- `사람 추가` 버튼으로 참가자를 계속 추가
- 참가자마다 이름과 전용 번호 입력 영역 제공
- 한 사람에게 여러 조합을 넣을 수 있으며 한 줄을 한 조합으로 인식
- 각 조합의 번호는 공백·쉼표·세미콜론으로 구분 가능
- 한 조합 안의 중복 번호는 허용하지 않음
- 참가자 이름과 입력한 번호는 `localStorage`에 저장되어 다음 접속에도 유지
- 추첨이 시작되는 순간 `참가자 번호` 섹션은 자동으로 접힘
- `접기 / 펼치기` 버튼으로 참가자 입력 영역을 다시 열 수 있음
- 실시간 추첨이 끝나면 모든 참가자의 모든 조합을 즉시 검사
- 참가자 카드 안에서는 각 조합의 일치 개수와 일치 번호를 상세 표시
- 별도의 `참가자 추첨 결과` 요약에서는 **일치 개수가 많은 그룹부터 내림차순**으로 모아 표시
- 같은 참가자가 같은 일치 개수의 조합을 여러 개 보유하면 참가자명 뒤 괄호에 해당 조합 수를 표시

예시:

```text
6개: 1참가자(1)
5개: 2참가자(2), 5참가자(1)
4개: 1참가자(4), 3참가자(1)
3개: 2참가자(3)
0개: 4참가자(5)
```

여기서 `1참가자(4)`는 `1참가자`가 **4개 일치한 서로 다른 조합을 4개 보유했다는 뜻**입니다. 한 참가자가 서로 다른 일치 개수의 조합을 가지고 있으면 해당 참가자는 여러 그룹에 각각 나타날 수 있습니다.

- 추첨 완료 후 참가자 번호를 추가하거나 수정하면 현재 추첨 결과 기준으로 요약과 상세 결과를 즉시 다시 계산
- 보너스 번호가 없으므로 등수 대신 `N개 일치` 기준으로 판정

## 이미지와 레이어

Base64나 별도 이미지 로더를 사용하지 않습니다.

```text
assets/Frame2.png
```

릴 Canvas는 PNG 프레임보다 낮은 `z-index`에 배치되어 입 구멍을 통해서만 보입니다. 페이지와 이미지가 축소·확대되어도 입 위치와 릴 크기는 비율로 함께 조정됩니다.

## 실행

별도 빌드 과정이 없습니다.

```bash
python -m http.server 8080
```

또는 GitHub Pages에서 `main` / `/ (root)`를 배포 대상으로 지정하면 바로 실행할 수 있습니다.
